# 1. 最终产品目标

ScreenRestore 最终不是文档扫描器，而是一个现实作品数字化恢复 App。

目标场景：

* 美术馆拍摄画作；
* 画展隔着玻璃拍摄作品；
* 文创店拍摄明信片；
* 拍摄海报、插画、摄影作品等平面视觉内容。

典型输入包含：

* 透视；
* 画框 / 卡纸 / 边框干扰；
* 镜头畸变；
* 反光；
* 顶灯高光；
* 不均匀照明；
* 色温变化；
* sensor noise；
* JPEG / HEIC；
* 轻微失焦；
* 手抖；
* 有效分辨率不足。

目标流水线：

```text
camera photo
→ target/content detection
→ content/outer semantic selection
→ lens correction
→ precise corner refinement
→ perspective rectification
→ color/illumination restoration
→ reflection/glare treatment
→ denoise/deblur
→ optional 2× restoration/SR
→ Fidelity
→ optional masked generative reconstruction
→ Enhanced
```

最终评价标准是：

> 是否更接近一张可信的作品电子版。

# 2. Fidelity 与 Enhanced

必须继续严格区分：

## Fidelity

只能使用观测支持的恢复：

* geometry；
* white balance；
* exposure；
* illumination；
* denoise；
* conservative deblur；
* reflection suppression；
* multi-frame observation fusion；
* conservative SR。

完全不可见区域标记：

```text
unresolved
```

不得暗中生成。

## Enhanced

允许：

* masked generative reconstruction；
* inpainting；
* perceptual SR；
* generative prior。

但必须标记：

```text
estimated
generated
```

禁止把生成结果伪装成原始像素。

# 6. 下载工具策略

不要所有数据都使用单连接 curl。

先检测：

```bash
command -v aria2c
command -v curl
command -v wget
command -v python3
command -v gdown
```

如果已有：

```text
aria2c
```

HTTP/HTTPS 大文件优先：

```bash
aria2c \
  -x 16 \
  -s 16 \
  -k 8M \
  --continue=true \
  --file-allocation=none \
  URL
```

根据服务器行为可把：

```text
-x / -s
```

调整为 8～16。

不要因为 16 个连接更“激进”就认为一定更快，实际测速决定。

如果 aria2 不存在：

优先：

```bash
curl -4 \
  --fail \
  --location \
  --retry 10 \
  --retry-delay 3 \
  --continue-at -
```

如果系统当前已经有代理设置：

先检测：

```bash
env | grep -i proxy || true
scutil --proxy || true
```

不要修改用户全局代理配置。

可以对单次下载比较：

```text
当前代理路径
IPv4
无 shell proxy
```

的短 range 下载速度，然后选择较快路径。

禁止为了下载自动修改 Clash / 系统全局代理 GUI。

# 26. Restoration 模型原则

* NAFNet-like；

* residual CNN；


-人脸；
-ringing；
